# qwiki

测试开发工作台的**项目文档仓库**：记录疑惑、思考与技术决断。

这里不写"代码怎么用"（那属于代码仓库的 README），而是回答：

- 我们想做成什么？→ [目标与范围](docs/00-vision.md)
- 还有哪些没想清楚的问题？→ [疑惑](docs/questions/README.md)
- 当时是怎么推演的？→ [思考](docs/thoughts/README.md)
- 为什么最终这样定？→ [技术决断](docs/decisions/README.md)
- qanvas、qcore 与 skill 分别指什么？→ [术语](GLOSSARY.md)

## 目录

| 目录 | 放什么 | 什么时候看 |
| --- | --- | --- |
| `docs/00-vision.md` | 定位、目标用户、范围与成功标准 | 判断某个需求该不该做 |
| `docs/questions/` | 开放的疑问，一事一件 | 开始调研或讨论前 |
| `docs/thoughts/` | 探索性笔记、方案对比、阅读记录 | 回顾推演过程 |
| `docs/decisions/` | 技术决断（ADR），编号且不改写 | 想知道"为什么是这样" |

## 写作约定

- 三个目录各有一份 README，说明命名方式与模板，先看那里。
- 疑惑和思考可以先写得很糙；决断一旦接受就固定下来，改变主意用新的一条取代旧条目。
- 文档之间用相对路径互相链接，别只把结论留在聊天记录里。
