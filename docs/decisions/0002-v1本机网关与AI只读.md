# 0002. v1：qanvas 本机网关，AI 经 qcore 只读访问

- 状态：已接受
- 日期：2026-10-25
- 相关：[q-0002](../questions/q-0002-连接信息分发还是代执行.md)、[q-0003](../questions/q-0003-qanvas部署形态.md)、[ADR 0001](0001-资源管理自研注册中心与执行路径.md)

## 背景

- qanvas 面向 QA（测试开发工程师，人类），桌面应用 + 执行网关。
- AI 通过 qcore CLI 调用 qanvas 接口，执行查找类工作。
- QA 是可信人类，暂不要求审计；AI 现阶段只开放只读，重点是防止误操作。

## 决策

1. **部署形态**：qanvas 采用本机服务。桌面应用与网关同机部署，qcore 调用本机接口；暂不引入共享服务。
2. **执行路径**：AI 只通过 qcore 访问 qanvas，由 qanvas 代执行；qcore 不持有资源凭据。
3. **只读范围**：v1 只开放资源列表 / 详情、连接校验、schema 查看、只读查询；不提供写接口。
4. **强制只读**：qanvas 服务端拒绝任何非只读动作，即使 qcore 护栏被绕过也无效；qcore 的护栏是第二层。
5. **QA 路径**：QA 直接在 qanvas 桌面端操作，暂不审计，不做凭据分发 / 短期凭据。
6. **AI 审计**：v1 只审计 AI 请求，记录主体、资源、语句、结果、耗时；本地存储，暂不做跨机器汇总。
7. **接口形态**：qcore 用稳定 CLI 契约（JSON 输出、固定退出码、版本协商），不引入 MCP。

## 备选方案

- **共享服务 + QA/AI 全量审计**：更适合团队和集中治理，但当前 QA 无审计要求，先不引入部署与运维成本。
- **AI 直连数据库**：无法在服务端强制只读，排除。
- **AI 走 DBX MCP**：把第三方权限模型当审计边界，且只覆盖数据库，排除。

## 后果

- AI 可用性依赖 qanvas 本机服务运行；qcore 在服务不可用时必须明确失败（fail closed）。
- 审计日志在本地；跨机器汇总 / 防篡改后续再补。
- 只读边界由 qanvas 服务端保证；qcore 护栏只减少误操作。
- 若未来开放 AI 写操作、跨机器访问或 QA 审计，需要新 ADR 重新评估。
