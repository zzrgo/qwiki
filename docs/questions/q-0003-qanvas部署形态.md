# qanvas 的部署形态：桌面单机还是团队共享服务？

- 状态：已解答
- 日期：2026-10-25
- 相关：[q-0001](q-0001-资源管理工具自研还是依托第三方.md)、[q-0002](q-0002-连接信息分发还是代执行.md)、[ADR 0001](../decisions/0001-资源管理自研注册中心与执行路径.md)

## 背景

qanvas 面向 QA，提供资源注册、执行网关和桌面应用；AI 通过 qcore 调用 qanvas 接口。需要确定 qanvas 的服务端跑在哪里：

- 每台 QA 机器一个桌面应用（资源、凭据、审计都在本地）？
- 还是有一个团队共享的 qanvas 服务，桌面端只是客户端？

这个选择决定审计能否集中、AI 是否依赖某台机器在线、凭据存在哪里、多人如何共享资源。

## 方案

### A. 桌面单机

注册中心、执行网关、凭据、审计都嵌在桌面应用里；qcore 调用本机接口。

- 优点：部署简单，离线可用，适合个人。
- 缺点：审计分散在各台机器；AI 使用时要求桌面应用在线；团队共享资源需要另想办法；凭据散落在每台机器。
- 适用：个人或小规模、无需集中审计。

### B. 桌面客户端 + 共享服务（推荐）

共享的 qanvas 服务持有注册中心、执行网关、凭据和审计；桌面应用是管理 / 审批 / 审计界面；qcore 调用共享服务。

- 优点：审计集中；AI 不依赖某个人的桌面应用；资源与凭据统一管理；可以做团队权限。
- 缺点：需要部署和运维服务；离线能力弱；桌面端与服务端的鉴权要做对。
- 适用：团队 QA、需要统一审计与权限。

### C. 混合

共享服务为准，桌面端缓存常用资源 / 支持离线查看；写操作与审计仍回服务端。

- 优点：兼顾体验与集中治理。
- 缺点：同步与冲突处理复杂，第一版不建议。

## 倾向

如果目标是团队 QA + AI 审计，选 B。桌面应用只做 UI，不要把网关和凭据锁在 UI 进程里；否则 AI 的可用性和审计完整性都依赖"某个人的桌面应用开着"。

即使是单机形态，也建议把网关做成独立进程 / 本地服务，桌面应用只是它的客户端；这样后续迁移到共享服务时不用重写执行路径。

## 待确认

- [x] 团队规模与是否需要共享资源？→ 面向 QA 人类，v1 本机使用。
- [x] 审计是否需要跨人 / 跨机器汇总？→ QA 暂不审计；AI 审计先本地存储。
- [ ] 是否要求离线可用？
- [x] qanvas 服务部署在内网服务器、单机容器，还是随桌面应用启动？→ 本机服务。

## 结论（2026-10-25）

v1 采用 **A：本机服务**。qanvas 桌面应用与执行网关同机；qcore 调用本机接口。桌面 UI 与网关仍建议分进程，避免 UI 退出导致 AI 不可用。

暂不引入共享服务；若未来需要跨机器访问、集中审计或团队共享资源，再评估 B。见 [ADR 0002](../decisions/0002-v1本机网关与AI只读.md)。
