# 连接信息：分发给调用方，还是由平台代执行？

- 状态：已解答
- 日期：2026-10-25
- 相关：[q-0001](q-0001-资源管理工具自研还是依托第三方.md)、[q-0003](q-0003-qanvas部署形态.md)、[ADR 0001](../decisions/0001-资源管理自研注册中心与执行路径.md)

## 背景

平台面向 QA 与 AI，数据校验 / 数据验证是高频操作；需要按主体做权限隔离和审计，重点是防止 AI 误操作造成破坏。

如果平台把连接信息（含凭据）返回给调用方，AI 就可以绕过平台直接连库，平台既无法审计"执行了什么"，也无法阻止 DDL / DELETE 等破坏性操作。因此，平台是"配置分发者"还是"执行代理"，决定了审计能力的天花板。

## 2026-10-25 补充：AI 路径已定

- AI 通过 `qcore` CLI 调用 qanvas 接口；qanvas 提供执行网关，代 AI 执行查找类工作。
- 因此 AI 路径确定为 **B（代执行）**，qcore 不持有资源凭据。
- qcore 客户端可以加一层护栏，但 AI 可以绕过 qcore 直接调 API，所以**策略与审计必须在 qanvas 服务端**；客户端护栏只做 UX 兜底。
- QA 的路径仍待定：走 qanvas 桌面端执行，还是领取短期凭据后直连。

## 方案

### A. 分发配置（credential broker）

平台校验资源可用性，向调用方发放连接信息或短期凭据。

- 优点：调用方可以继续用现有工具；平台实现简单。
- 缺点：只能审计"谁领了什么"，不能审计"执行了什么"；无法阻止 AI 直接执行破坏性操作；凭据扩散，轮换困难。
- 适用：只有可信的 QA 人类、且没有 AI 写入需求的场景。

### B. 代执行（execution gateway）

平台接收请求（QA CLI / API / AI 的 qcore），做策略判断后代连执行，返回结果；凭据不出平台。

- 优点：可做语句级审计、只读默认、写操作审批、行数 / 超时限制；AI 不接触凭据；QA 与 AI 共用一套审计。
- 缺点：平台成为关键路径；需要按资源类型实现 adapter；工具粒度设计不好会限制正常使用。
- 适用：有 AI 参与、需要防误操作、需要统一审计的场景。

### C. 混合

QA 人类走分发（短期、最小权限凭据，配合库侧审计）；AI 走代执行。

- 优点：兼顾 QA 的自由度与 AI 的安全边界。
- 缺点：两条路径，审计分散；策略要按主体类型分流。

## 倾向

- AI 路径必须走 B，且默认只读；写操作按风险分级审批。
- QA 若确实需要直连（自己的脚本 / 客户端），走 C：短期凭据 + 最小权限账号 + 库侧审计，但平台要记录凭据发放。
- 不建议把 A 用于 AI。
- 执行网关先支持最常用的 2–3 种资源，按 adapter 扩展；不要一开始覆盖所有数据库和 MQ。

## 对执行网关的最小要求

- **主体**：区分 QA 用户与 AI（agent ID + task ID + 发起人），每次请求都带主体信息。
- **策略**：资源 allowlist、环境隔离（AI 默认只能碰 test / staging）、语句类型白名单、行数 / 超时 / 并发限制。
- **审批**：DDL / DROP / TRUNCATE / 无 WHERE 的 UPDATE / DELETE 等高风险操作，展示完整语句并由人工确认；审批结果入审计。
- **审计**：append-only，记录主体、资源、语句、策略决定、审批人、结果、耗时；与业务库分离存储，必要时做防篡改。
- **凭据**：Vault / KMS / Keychain 管理；AI 使用只读账号；写账号只在网关内使用；定期轮换。
- **接口**：AI 侧提供细粒度工具（`list_resources`、`validate_connection`、`query_readonly`、`request_write`），不要给一个无差别的 `execute_sql`。
- **客户端护栏**：qcore 只做安全默认值、参数校验、结果截断 / 脱敏、明确报错；不要依赖它做权限判断。

## 待确认

- [x] 平台"校验连接信息"是指连通性 / 凭据有效性校验 → 按健康检查理解，不返回凭据。
- [x] QA 的 CLI 是否必须直连数据库 / 消息中间件？→ 不需要，QA 直接在 qanvas 桌面端操作。
- [x] AI 的写操作是一律人工审批，还是按资源 / 环境分级？→ v1 不开放写操作。
- [ ] 首批要支持哪些资源类型？

## 结论（2026-10-25）

- AI：走 B，qcore → qanvas 本机网关，只读；qanvas 服务端强制只读，qcore 护栏为第二层。
- QA：可信人类，暂无审计要求；直接在 qanvas 桌面端操作，不需要凭据分发 / 短期凭据机制。
- v1 不做写审批流；未来开放 AI 写操作时再补。
